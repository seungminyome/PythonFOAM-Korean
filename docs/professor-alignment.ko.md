# 교수님 제안과 지금 결과의 거리 · 2026년 10월 18일 점검

[프로젝트 첫 화면](../README.md) · [날짜별 작업](progress.ko.md) · [10월 17일 시험](results.md)

10월 8일 교수님은 **PythonFOAM에 공개된 경량 멀티모달 언어 모델을 연결해, OpenFOAM 계산 도중 나온 상태를 읽고 사용자에게 분석을 제공할 수 있는지** 살펴보자고 제안했습니다. [Gemma 4 12B 모델](https://huggingface.co/google/gemma-4-12B-it-qat-q4_0-unquantized)은 예시로 들었습니다. 이메일에는 SVD, 고체 솔버, 힘의 평형, 언로딩 실패 예측, AI의 솔버 제어가 필수 조건으로 적혀 있지 않습니다. 그 항목들은 내가 답장에서 생각해 보겠다고 한 방향이므로, 교수님이 요구한 성과처럼 말하지 않겠습니다.

**판단: 첫 통합 시제품으로는 제안의 중심을 따라갔지만, 사용자에게 믿고 쓸 수 있는 분석을 제공했다는 단계는 아닙니다.** 계산 중 실제 수치와 그림이 로컬 모델에 도착하고 답변을 저장한 뒤 계산이 이어지는 것까지 확인했습니다. 반면 가장 빠른 유동의 위치를 묻는 작은 시험에서는 답변 여섯 개가 모두 틀렸고, 이미지 요청 한 번에 계산이 약 78초 멈췄습니다. 모델이 맞게 인용한 최대 속력 수치는 애초에 입력에 있었으므로 공간 분석 능력의 증거가 아닙니다.

| 교수님 제안에서 따져 볼 점 | 지금 확인한 것 | 판정 |
|---|---|---|
| PythonFOAM **안에서** 계산 중 솔버 상태를 읽는가? | PODFoam의 완료된 계산 단계에서 Python 콜백이 수치와 속력·압력 자료를 받습니다. 5단계의 요청 후 10단계까지 계산한 기록이 있습니다. | 한 가지 직렬 유체 예제에서 확인 |
| 공개된 경량 **멀티모달** 모델인가? | 로컬 CPU의 Gemma 4 **E2B Q4_0**에 수치 요약과 같은 단계의 PNG를 보냈습니다. 사용한 [모델 파일](https://huggingface.co/ggml-org/gemma-4-E2B-it-GGUF/blob/main/gemma-4-E2B-it-Q4_0.gguf)과 [이미지 변환기](https://huggingface.co/ggml-org/gemma-4-E2B-it-GGUF/blob/main/mmproj-gemma-4-E2B-it-Q8_0.gguf)의 SHA-256은 [실행 환경 기록](evidence/2026-10-17/runtime-summary.json)과 같습니다. 교수님이 예시로 든 12B를 실행한 것은 아닙니다. | E2B로 확인; 12B 비교는 없음 |
| 사용자에게 **유용한 분석**을 주는가? | 답변을 파일로 받았지만, 저장된 한 상태를 여섯 번 물었을 때 최대 속력 위치를 모두 틀렸습니다. 수치만 받은 세 답변의 평면 오차는 60.92 cm, 그림을 더한 세 답변은 50.97 cm였습니다. 여섯 번은 서로 다른 유동 사례 여섯 개가 아닙니다. | 아직 입증하지 못함 |
| 계산을 방해하지 않고 쓸 수 있는가? | AI를 끄거나, 수치만 보내거나, 그림을 보내거나, 연결이 거부되거나, 응답이 시간 초과된 다섯 실행은 모두 10단계를 마쳤습니다. 기준 외 네 실행의 저장 파일은 각각 45개가 기준과 같았습니다. 그러나 그림 요청 중 솔버가 약 78초 기다렸습니다. | 이번 실행의 결과 보존·실패 처리는 확인; 대기 시간은 큼 |
| 다른 문제에도 통하는가? | 공개된 핵심 검증은 PODFoam의 짧은 직렬 유체 사례 한 가지입니다. MPI, 장시간 계산, 여러 유동장, 실제 사용자 질문은 시험하지 않았습니다. | 미검증 |

판정의 근거는 [10월 17일 실행 보고서](results.md), [다섯 솔버 실행의 검증 파일](evidence/2026-10-17/pod-llm-demo.LRfJBN/demo-verification.json), [그림 유무 비교 검토](evidence/2026-10-17/independent-ablation-review.json)입니다. 45개 파일의 일치는 **이 실행에서 콜백 때문에 저장 결과가 달라지지 않았다는 뜻**입니다. 유동이 물리적으로 옳다거나 모든 조건에서 안전하다는 증거로 확대하지 않겠습니다.

그림을 넣은 답이 약 10 cm 가까웠다는 숫자도 성공 판정으로 쓰기 어렵습니다. 여섯 요청 모두 같은 계산 상태를 되풀이해 물었고, 두 조건 모두 정답에서 50 cm 이상 벗어났습니다. 이 시험은 이미지가 실질적으로 도움이 되는지 결론을 내리기에는 작습니다.

## 방향을 흐릴 수 있는 부분

- **SVD(Singular Value Decomposition, 특잇값 분해)**는 기존 PODFoam 예제에서 계산한 스냅샷을 요약하는 방법입니다. 지금 입력에도 일부 남아 있지만, 그 값이 모델 답변을 개선했는지는 시험하지 않았습니다. 첫 모드의 높은 비율을 AI 정확도나 유동 안정성으로 설명하면 잘못입니다. 교수님 제안의 중심은 SVD가 아니라 계산 중 모델이 실제 상태를 읽고 쓸 만한 관찰을 제공하는지입니다.
- 내가 답장에서 말했던 **힘의 평형**은 현재 입력에서 계산하지 않습니다. 실제로 보내는 것은 선형 방정식 풀이의 잔차, Courant 수, 연속성 오차 같은 진단값입니다. 잔차를 힘의 평형으로 바꾸어 부를 수 없습니다. [콜백 요약 코드](../Solver_Examples/PODFoam/llm_demo/python_module.py)는 `force_equilibrium`을 미구현으로 기록합니다.
- **고체 솔버·언로딩 실패 조기 발견**은 별도 적용 아이디어입니다. 10월 11일의 고체 예제는 이미지 전달 가능성을 보여주지만 [두 단계의 작은 별도 시험](progress-evidence/2026-10-11-solid-image-verification.json)입니다. 언로딩 실패 탐지 성능은 측정하지 않았습니다. 교수님께 첫 성과를 설명할 때 PODFoam 안의 연동 결과와 섞지 않겠습니다.
- **모델이 계산을 제어한다**는 설명은 현재 코드와 맞지 않습니다. 답변은 기록만 하고 U, p, 설정으로 되돌려 넣지 않습니다. 현재 구조는 관찰·기록용입니다.

## 다음에 확인해야 할 것

우선 같은 질문을 **서로 다른 계산 시점과 유동 사례**에 던져 위치·방향·이상 징후를 원본 장과 대조해야 합니다. 숫자만 준 경우, 숫자와 그림을 준 경우를 같은 입력 조건에서 비교하고, 엉뚱한 말을 했는지도 사람이 읽어 확인해야 합니다. 그 결과가 좋아야 ‘사용자를 위한 분석’이라는 주장에 힘이 생깁니다.

그다음에는 상태를 복사해 고정한 뒤 모델 요청을 별도 작업으로 보내, 모델을 기다리는 동안 솔버가 계속 계산할 수 있는지 시험해야 합니다. 12B 예시 모델과의 비교는 같은 과제와 장비 조건을 맞춘 뒤에 할 일입니다. 지금 자료로는 더 큰 모델이 더 정확하거나 빠를 것이라고 말할 수 없습니다.

교수님께 지금 보고한다면 이렇게 표현하는 게 정확합니다. **“PythonFOAM의 PODFoam 계산 중 상태를 로컬의 공개·양자화 멀티모달 모델에 전달하고 답변을 기록하는 시제품을 만들었습니다. 답변을 받은 뒤 솔버가 계속 계산했고, 시험한 저장 결과는 기준 실행과 같았습니다. 다만 한 상태의 위치 질문에서는 모델 답변이 모두 틀렸고, CPU 이미지 요청 동안 계산이 약 78초 기다렸습니다. 다음에는 여러 상태에서 분석의 유용성을 검증하고 대기 시간을 줄이겠습니다.”** 첫 진행 보고로는 충분하지만, 연구 기여의 효과가 검증됐다고 말하기에는 이릅니다.
