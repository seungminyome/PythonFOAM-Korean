# 작업 기록, 10월 8일부터

[프로젝트 소개](../README.md) · [10월 17일 시험 결과](results.md)

### 10월 8~10일 · 수치 입력 연결

8일에 과제가 시작됐고, 9일에 [원본 저장소](https://github.com/argonne-lcf/PythonFOAM)를 내려받았습니다. 10일에는 PODFoam 계산 중 수치 요약을 로컬 Gemma에 보내 답을 받았습니다. [당시 검증 파일](progress-evidence/2026-10-10-pod-text-verification.json)에는 10단계 계산과 저장 파일 비교가 남아 있습니다. 이미지 입력은 없었습니다.

### 10월 11~13일 · 그림을 PODFoam 안으로

11일에는 [별도 고체 솔버 예제](progress-evidence/2026-10-11-solid-image-verification.json)에서 숫자와 그림 한 장을 보내 봤습니다. PODFoam에서 그림을 보낸 기록은 13일부터입니다. 12일에 이미지 요청 코드를 PODFoam 쪽에 작성했고, 13일에 [연결 코드](https://github.com/seungminyome/PythonFOAM-Korean/commit/e9b3598)와 [모델 요청 예제](https://github.com/seungminyome/PythonFOAM-Korean/commit/f053736)를 정리해 실제 실행을 확인했습니다. 5단계에서 수치·그림을 보낸 뒤 솔버가 10단계까지 계산했습니다. [첫 실행 보고서](results-20261013.md)에 당시 답변과 시간도 있습니다.

### 10월 14~16일 · 답변 검토와 비교 준비

14일에는 [그림 해설 초안](progress-evidence/2026-10-14-overview-draft.html)을 만들었습니다. 15일에는 저장된 계산값으로 AI의 위치 답변을 [재검사](evidence/2026-10-13/numeric_audit_20261015.json)했습니다. 16일에는 질문과 수치를 고정하고 PNG 포함 여부만 바꾸는 요청 6개를 준비해 [오프라인 검사](progress-evidence/2026-10-16-offline-check.json)를 했습니다.

### 10월 17~18일 · 통제 실행과 자료 공개

17일에는 모델을 끈 경우, 숫자만 보낸 경우, 그림까지 보낸 경우, 연결 거부와 시간 초과까지 [다섯 번 솔버를 실행](results.md)했습니다. 모두 10단계를 마쳤고, 기준 외 네 실행의 저장 파일은 각각 45개씩 기준과 같았습니다. 한 계산 상태로 그림 유무를 비교한 모델 답변 6개는 최대 속력의 위치를 모두 틀렸습니다. 18일에는 새 계산 없이 이 결과와 원본 자료를 [한국어 저장소의 다운로드 자료](https://github.com/seungminyome/PythonFOAM-Korean/releases/tag/korean-docs-2026-10-18)로 정리했습니다.

### 10월 19일 · 반복 실행과 12B 쌍별 재생

같은 컴퓨터와 서버로 다섯 조건과 쌍별 재생을 [다시 실행](evidence/2026-10-19/README.md)했습니다. 5단계 배열과 그림의 해시, 재생 답 여섯 개의 좌표가 모두 17일과 같았습니다(답의 문장은 일부 달라짐). GPU 노드에서 Gemma 4 12B로 같은 측정을 되풀이할 [스크립트](../Solver_Examples/PODFoam/llm_demo/hpc/README.md)를 넣었고, 그중 쌍별 재생을 MedicineBow의 NVIDIA A30에서 돌렸습니다(Slurm 작업 24696203). 여섯 답 모두 위치를 모른다고 해 위치 오차를 잴 수 없었습니다([결과](results.md#gpu에서-gemma-4-12b로-같은-재생-2026-10-19), [근거](evidence/2026-10-19-12b/README.md)). 영문 저장소의 CI 설정과 문서를 정리했습니다.

### 10월 20일 · 비동기 요청, 스냅샷 설명, 스냅샷 연속

교수의 제안대로 세 가지를 만들었습니다. 요청을 비동기로 보내 솔버가 기다리지 않게 했고(3000걸음 실행에서 요청 걸음 0.004~0.006 s, 답은 843·1071걸음 뒤에 도착, 저장 필드 216개 모두 기준과 동일), 그림 한 장을 설명하게 했고, 그림 세 장을 주고 변화를 물었습니다. 저장한 프레임으로 [재생](results-20261020.md)해 채점한 결과, 가장 빠른 곳은 18번 모두 틀렸고 최고 속력의 추세는 두 보기 모두 거꾸로 답했습니다. 근거는 [2026-10-20 폴더](evidence/2026-10-20/README.md)에 있습니다.

### 10월 21~22일 · 그림 읽기 시험

21일에는 읽기 쉽게 다시 그린 그림(그림 한 장에 필드 하나, 퍼센트 축과 격자)과, 정답을 미리 정해 둔 그림 요청 308개를 만들었습니다. 위치를 정해 둔 합성 그림, 저장 상태에 봉우리와 골을 심은 그림, 세 시각짜리 합성 추세 그림이 들어 있습니다. 22일에 MedicineBow의 NVIDIA RTX A6000 한 장에서 Gemma 4 모델 일곱 개(E2B 세 가지, E4B, 12B, 26B-A4B, 31B)에 차례로 보냈습니다(Slurm 작업 24756981, 83분). 새 그림에서 12B, 26B-A4B, 31B는 합성 그림 32장 모두에서 가장 빠른 곳을 10 % 안에 짚었고, 지금 솔버의 그림에서는 9~18장이었습니다. 위치 문항 네 가지 모두에서 E2B 세 가지는 어느 그림이든 32장 중 1~12장이었습니다(답 하나로 고정하면 5장이나 6장). 심은 그림의 가장 낮은 압력에서는 큰 모델들이 계단 모서리로 끌렸고, 12B는 저장 상태의 압력 추세를 14개 중 11개에서 거꾸로 읽었으며, 추세 채점의 2 % 기준을 프롬프트에 적지 않은 잘못도 찾았습니다([보고서](results-20261022.md), [근거](evidence/2026-10-22-picture-test/README.md)).

### 참고

9일 복제와 12일 초안은 로컬 git 기록에, 10~11일 실행은 보관한 검증 파일에 남아 있습니다. 12일 초안은 13일 코드로 바뀌었습니다.

13일에 적은 위치 오차 약 25 cm는 x축만 잰 값입니다. [17일 보고서](results.md)의 60.92·50.97 cm는 x-y 평면 거리라 두 숫자로 성능 변화를 비교할 수는 없습니다.
