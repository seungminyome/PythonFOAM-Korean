# PythonFOAM 작업 기록 · 2026년 10월 8~18일

[프로젝트 소개](../README.md) · [교수님 제안과 현재 결과](professor-alignment.ko.md) · [10월 17일 시험 결과](results.md)

처음에는 계산 중 나온 숫자를 모델에 보내는 것부터 시작했습니다. 그다음 같은 시점의 유동 그림을 보냈고, 마지막으로 답변이 맞는지와 모델 호출이 계산을 방해하는지 확인했습니다.

### 10월 8~10일 · 제안을 받고 첫 호출까지

8일에 교수님이 PythonFOAM 안에서 공개된 경량 멀티모달 모델을 써 보자고 제안했습니다. 9일에는 [원본 저장소](https://github.com/argonne-lcf/PythonFOAM)를 내려받았습니다. 10일에는 PODFoam 계산 중 수치 요약을 로컬 Gemma에 보내 답을 받았습니다. [당시 검증 파일](progress-evidence/2026-10-10-pod-text-verification.json)에 10단계 계산과 저장 파일 비교가 남아 있습니다. 이때 보낸 것은 **숫자뿐**이었습니다.

### 10월 11~13일 · 그림을 PODFoam 안으로

11일에는 [별도 고체 솔버 예제](progress-evidence/2026-10-11-solid-image-verification.json)에서 숫자와 그림 한 장을 보내 봤습니다. PODFoam에서 그림을 보낸 기록은 13일부터입니다. 12일에 이미지 요청 코드를 PODFoam 쪽에 작성했고, 13일에 [연결 코드](https://github.com/seungminyome/PythonFOAM-Korean/commit/e9b3598)와 [모델 요청 예제](https://github.com/seungminyome/PythonFOAM-Korean/commit/f053736)를 정리해 실제 실행을 확인했습니다. 5단계에서 수치·그림을 보낸 뒤 솔버가 10단계까지 계산했습니다. [첫 실행 보고서](results-20261013.md)에 당시 답변과 시간도 있습니다.

### 10월 14~16일 · 첫 답변을 다시 읽고 비교 준비

14일에는 연결 과정을 설명하는 [그림 해설 초안](progress-evidence/2026-10-14-overview-draft.html)을 만들었습니다. 15일에는 저장된 계산값을 다시 읽어 AI가 말한 빠른 유동의 위치가 얼마나 어긋났는지 [재검사](evidence/numeric_audit_20261015.json)했습니다. 16일에는 같은 질문과 수치를 쓰되 그림만 넣거나 빼는 요청 6개를 준비하고 [오프라인 검사](progress-evidence/2026-10-16-offline-check.json)를 했습니다. 14~16일의 작업은 기존 결과를 읽고 다음 시험을 준비하는 일이었습니다.

### 10월 17~18일 · 다시 돌려 보고 공개

17일에는 모델을 끈 경우, 숫자만 보낸 경우, 그림까지 보낸 경우, 연결 거부와 시간 초과까지 [다섯 번 솔버를 실행](results.md)했습니다. 모두 10단계를 마쳤고, 기준 외 네 실행의 저장 파일은 각각 45개씩 기준과 같았습니다. 한 계산 상태로 그림 유무를 비교한 모델 답변 6개는 최대 속력의 위치를 모두 틀렸습니다. 18일에는 새 계산 없이 이 결과와 원본 자료를 [한국어 저장소의 다운로드 자료](https://github.com/seungminyome/PythonFOAM-Korean/releases/tag/korean-docs-2026-10-18)로 정리했습니다.

8일은 제안받은 날입니다. 9일 저장소 복제와 12일 초안은 로컬 Git 기록에서, 10~11일 실행은 당시 보관한 검증 파일에서 확인했습니다. 12일 초안은 13일에 교체돼 지금 공개 브랜치에는 없습니다. 13일 이후 코드는 위에 연결한 커밋에서 볼 수 있습니다.

13일에 적은 위치 오차 약 25 cm는 x축만 잰 값입니다. [17일 보고서](results.md)의 60.92·50.97 cm는 x-y 평면 거리라 두 숫자로 성능 변화를 비교할 수는 없습니다.
