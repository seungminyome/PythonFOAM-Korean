## 목적과 시험 범위

이 시제품은 PythonFOAM 콜백을 이용한 계산 중 관찰·기록 시스템입니다. 실행 중인 OpenFOAM 솔버의 상태를 읽어 로컬 멀티모달 모델에 관찰 답변을 요청합니다. 사용자가 읽을 답변을 저장하며, 그 답변으로 필드 값, 시간 간격, 솔버 설정이나 제어 알고리즘을 바꾸지 않습니다.

20,540개 셀로 구성된 PODFoam 유체 사례를 직렬로 실행했습니다. 한 단계의 시간 간격은 10⁻⁷ s이고, 총 10단계를 계산했습니다. 5단계가 끝난 t = 5 × 10⁻⁷ s에 관찰을 요청한 뒤 10단계까지 진행했습니다. 초기의 짧은 구간에서 연결을 확인한 시험이며, 긴 시간 동안의 유동을 검증한 결과는 아닙니다.

## 자료가 전달되는 과정

```text
PODFoam: 5단계 계산 완료
    |
    +-- 속도 스냅샷, 압력, 격자 형상, 수치 진단값
    |
Python 콜백: 수치를 요약하고 같은 단계의 필드 그림 생성
    |
로컬 llama.cpp 서버: Gemma 4 E2B Q4_0와 이미지 프로젝터
    |
요청, 응답, 소요 시간 기록
    |
PODFoam: 6–10단계 계산 계속
```

콜백이 입력을 준비하고 응답을 요청한 뒤 결과를 기록하는 동안 솔버는 기다립니다. 별도 작업 프로세스를 사용해 시험에서 정한 대기 시간 안에 복귀하도록 했지만, AI가 답을 만드는 동안 솔버가 동시에 진행하는 구조는 아닙니다.

입력에는 단계와 시각, 셀 수, 정규화한 선형 솔버 잔차, Courant 수와 연속성 진단값, 속도 성분별 SVD 요약, 640×360 PNG가 포함됐습니다. 그림 위쪽에는 속도 크기, 아래쪽에는 운동학적 압력을 표시했습니다. 같은 단계의 셀 값과 다각형을 사용했고, 셀 사이의 색을 보간하지 않았습니다. 길고 얇은 영역을 보기 쉽도록 세로로 늘려 그렸습니다.

필드의 값 범위와 영역의 좌표 범위도 수치로 전달했습니다. 특히 최대속도 값은 수치 입력에 이미 들어 있습니다. 이 숫자를 맞게 인용했다는 것만으로 모델이 그림에서 값을 읽어냈다고 판단할 수는 없습니다.

## 검사한 항목

검증 코드는 상태 기록과 솔버 로그를 대조하고, 단계와 시각이 일치하는지 확인합니다. 그림에 사용한 배열을 저장된 계산 필드와 비교하고, 요청에 기록된 PNG가 포함됐는지 검사합니다. 관찰 호출이 끝난 뒤 6단계로 진행하는지도 확인합니다. 또한 저장된 필드 파일을 AI 요청이 없는 기준 실행과 비교하고, 전체 콜백 시간이 정해진 기한과 마무리 여유 안에 들어오는지 검사합니다.

| 조건 | 모델 호출 결과 | 완료 단계 | 기준 실행과 일치한 파일 | C++에서 잰 전체 콜백 시간 |
|---|---|---:|---:|---:|
| AI 요청 없음 | 요청 비활성화 | 10 | 기준 실행 | 0.754688 s |
| 수치 요약 + 이미지 | 응답 수신 | 10 | 45 / 45 | 70.604411 s |

| 연결 거부 | 오류 기록 | 10 | 45 / 45 | 0.411067 s |

비교한 45개 파일은 10단계의 U, p, phi 파일과 마지막 단계의 POD 모드 파일 15개입니다. 독립적인 물리 실험을 45번 했다는 뜻이 아닙니다. 파일 일치는 이 조건들에서 저장된 계산 결과가 바뀌지 않았다는 근거이며, 일반적인 수치 안정성을 증명하지는 않습니다. AI 요청이 없는 조건에서도 관찰 자료를 준비하고 그림을 만들었으므로, 관찰 기능의 비용을 모두 제거한 실행과는 다릅니다.

일반 AI 호출의 작업 기한은 120 s였습니다. 연결 거부와 지연 응답 시험은 4 s로 설정했고, 프로세스 정리와 실행 지연의 여유를 포함한 통과 기준은 4.27 s였습니다. 기록된 조건에서 복귀한 결과이며, 모든 운영체제 지연이나 장애를 다룬 시험은 아닙니다. 별도의 고체 하중 제거 경로에서 과거에 발생한 시간 제한 실패가 이번 POD 결과로 해결됐다고 볼 수도 없습니다.

## 모델 답변과 계산 필드 비교

이미지를 받은 모델은 다음과 같이 답했습니다. 아래는 당시 영어 응답 원문입니다.

> The velocity magnitude |U| shows a high value near x=0.25 m, with a maximum of 82.5 m/s.

모델은 x축 영역의 가운데에 빠른 흐름이 모여 있다고 설명하고, 그 부근에 큰 압력 기울기가 있다고 주장했습니다.

저장된 필드 배열을 직접 확인한 결과는 다음과 같습니다.

| 항목 | 결과 |
|---|---|
| 최대 속도 크기 | 82.5275161154 m/s |
| 최대속도 셀 번호 · 0부터 셈 | 12090 |
| 해당 셀의 중심 | x = 0.0005381681 m, y = 0.0127144842 m |
| 최소 운동학적 압력 | −9362.82606697 m²/s² |
| 최소압력 셀 번호 · 0부터 셈 | 10409 |
| 해당 셀의 중심 | x = 0.0005390477 m, y = 0.0126848045 m |
| 모델의 x = 0.25 m와 최대속도 셀의 실제 x 사이 거리 | 0.2494618319 m |

최대속도와 최소압력은 가까운 **서로 다른 셀**에서 나왔습니다. 두 셀이 가깝다는 사실만으로 압력 기울기의 크기를 확인할 수는 없습니다. 최대속도 셀은 그림의 x축 범위에서 왼쪽으로부터 약 72% 지점에 있으며 중앙이 아닙니다. 이 응답은 위치를 정확히 찾았다는 근거가 되지 못합니다.

수치만 받은 답변은 입력에 있던 압력 잔차와 Courant 평균을 맞게 인용했고, SVD 첫 모드 비율이 높다고 말했습니다. 한편 잔차가 힘의 평형인지, SVD에서 평균을 제거했는지 확인하라고 했는데, 두 항목은 입력에 이미 설명돼 있었습니다. 주어진 값을 맞게 인용하는 능력과 유용한 해석을 제공하는 능력은 따로 평가해야 합니다.

## SVD 요약을 읽는 방법

SVD는 **Singular Value Decomposition, 특이값 분해**, POD는 **Proper Orthogonal Decomposition, 고유직교분해**입니다. 이 예제에서는 SVD로 저장된 속도 스냅샷을 요약합니다. AI 모델을 학습시키는 작업은 아닙니다.

모델에 보낸 요약은 첫 다섯 스냅샷을 사용하며, Ux, Uy, Uz를 각각 계산합니다. 각 성분의 행렬은 20,540행과 5열입니다. 시간 평균을 빼지 않았고, 셀 부피나 밀도에 따른 가중치도 적용하지 않았습니다.

| 속도 성분 | 다시 계산한 첫 특이값 제곱의 비율 |
|---|---:|
| Ux | 0.999969763560 |
| Uy | 0.999912946318 |
| Uz | 0.999995496959 |

비율은 σ₁² / Σᵢσᵢ²입니다. 스냅샷 행렬의 제곱합에서 첫 모드가 차지하는 몫을 뜻합니다. 모델 정확도나 안정성의 증명, 실제 운동에너지 비율을 측정한 값이 아닙니다. 평균을 빼지 않으면 평균 흐름의 큰 공통 부분이 비율을 지배할 수 있습니다. Uz는 특이값 자체가 거의 0이므로, 비율이 높다고 평면 밖 방향의 움직임이 중요하다고 해석하면 안 됩니다.

원래 POD 계산은 별도로 10개 스냅샷을 모아 성분별 모드 5개를 저장합니다. 5단계에서 모델에 보낸 요청에는 이후 6–10단계의 스냅샷을 사용하지 않았습니다.

## 실행 시간과 자원 사용

OpenFOAM v2106, Python 3.10, CPU로 실행한 llama.cpp b11429 서버를 사용했습니다. 모델 스레드는 4개, 컨텍스트 크기는 2048이었습니다. 기록된 모델 이름은 `gemma-4-E2B-it-Q4_0-vision`이며, 12B 모델이 아닙니다.

| 측정 항목 | 수치 + 이미지 | 수치만 |
|---|---:|---:|

## 당시 시험의 한계와 후속 평가

10월 13일의 이미지 조건과 수치만 보낸 조건은 시스템 지시문과 추가 수치 정보가 달랐습니다. 따라서 답변이 달라졌다는 것만으로 그림의 효과를 입증할 수 없습니다.

이후 작성한 [통제 재생 비교 도구](../Solver_Examples/PODFoam/llm_demo/README.md)는 모델, 질문, 수치 정보와 설정을 같게 유지하고 이미지 첨부만 바꿉니다. 이 도구로 수행한 새 비교는 [10월 17일 보고서](results.md)에 있습니다.

여러 상태와 반복 시험에서 살펴볼 항목은 위치 오차, 근거 없는 주장, 정보가 없을 때의 대응, 사용자 과제의 정답률, 소요 시간입니다. 최대속도 숫자를 입력에 이미 줬다면 그 값을 맞게 인용한 것을 그림 이해의 근거로 세면 안 됩니다. x축 위치만 답했다면 x축 오차를 계산할 수 있을 뿐, 전체 공간 거리를 구할 수는 없습니다. 자동 주장 검사는 사람이 검토할 항목을 표시하는 도구이며, 환각 여부를 완전히 판정하지는 않습니다.

재생 비교는 저장된 상태를 사용합니다. 그 요청·대기 시간은 실행 중 수치 요약과 그림 생성까지 포함한 위 표의 C++ 콜백 시간과 다릅니다. 도구를 준비하거나 모의 응답 테스트를 통과했다는 사실만으로 이미지가 답변을 개선했다는 새 근거가 생기는 것은 아닙니다.

MPI 실행, 실제 3차원 사례의 대체 이미지 생성 경로, 다른 솔버 계열, 더 큰 모델, 긴 실행, 공학적으로 유용한 분석, 실패 조기 예측은 이 10월 13일 시험에서 입증한 범위에 포함되지 않습니다.
