2026-10-17 · OpenFOAM v2106 · Gemma 4 E2B · 실행 코드 23089bb

5개 조건 모두 10단계를 완료했다. 기준 외 네 실행의 저장 파일은 각각 45/45개가 기준과 같았다. 연결 실패와 시간 초과 뒤에도 솔버는 진행했다.

1. 솔버 실행과 실패 처리

이 표의 시간은 C++에서 Python 분석 함수를 호출하기 직전부터 돌아온 직후까지 잰 값이다. 그보다 앞서 C++에서 수행한 계산값 복사와 진단 수치 준비는 포함하지 않는다. 두 정상 AI 호출은 기존 데모 방식이며 질문과 입력 정보가 달라서, 그림의 효과를 판정하는 통제 비교로 쓰지 않는다.

2. PNG 포함 여부 비교

같은 질문·같은 수치·같은 모델 설정에서 PNG 첨부만 바꿨다. 한 시점의 자료로 3쌍, 총 6회 요청했다. 정답 좌표는 채점에만 사용했다.

실제 최대속도 셀 중심: x≈0.000538m, y≈0.012714m. 최대속도는 약82.53m/s이며 이 속도 숫자는 두 조건 모두 입력에 들어 있다.

10월 19일에 같은 요청 6개를 모델 이름만 바꿔 GPU 노드의 Gemma 4 12B에 다시 보냈다. 6개 답변 모두 위치를 모른다고 해서 위치 오차를 잴 수 없었다. 12B 쌍별 재생 · 원본 자료

10월 22일에 같은 요청 6개를 프롬프트 캐시를 켜고 한 번, 끄고 한 번, E2B 세 가지와 E4B·12B·26B-A4B·31B에 다시 보냈다. E2B는 세 가지 모두 12번 다 공개된 답과 같은 좌표를 댔다. 나머지 모델은 채점기가 읽는 observations에 12번 모두 위치를 모른다고 적어 채점된 위치가 없었고, 그림을 받은 12B·26B-A4B·31B는 해석란에 빠른 흐름이 x = 0 m 근처라고만 적었다. 10월 22일 보고서 · 원본 자료

비교 범위
10월 13일의 약25cm는 x축 오차이고, 위 수치는 x-y 평면 거리다. 응답 시간은 프롬프트 캐시 조건도 달라 이미지의 추가 비용으로 해석할 수 없다.

3. 자동 채점과 원본 대조 검토

위치 오차 계산은 6개 답변 모두 정상 작동했다. 별도의 자동 근거 검사에서는 6개 모두 표시가 없었지만, 독립 검수에서는 잘못된 위치 주장과 추가 문제를 확인했다. 따라서 “자동 표시 없음”을 “환각 없음”으로 해석하면 안 된다.

4. 이번 시험의 범위

SVD(Singular Value Decomposition, 특잇값 분해) 요약은 유지했다. SVD를 뺀 경우와 비교하지 않았으므로, 이번 결과로 SVD의 필요성을 판정할 수 없다. 한 시점의 반복 결과이므로 여러 유동 상태에서 같은 성능이 나온다는 증거도 아니다.

시험 당시 코드는 23089bb이며, 이 페이지는 그 실행 기록을 게시한 것이다. 게시를 위한 문서 변경과 실제 시험을 구분한다. 실행한 모델과 프로젝터의 해시는 기존 고정값과 일치했다.
