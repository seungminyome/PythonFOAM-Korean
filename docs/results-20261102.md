openfoam.com에서 외부 보정이 하나이면, 단순한 `pEqn.solve()`는 한 시간 단계의 모든 압력
풀이에 `pFinal` 솔버를 씁니다. `pimpleFoam`은 마지막 풀이에만 쓰고, PR 브랜치도 이제 그렇게
합니다. OpenFOAM 8에서는 단순한 호출이 이미 `pimpleFoam`처럼 동작합니다.

`6fde869`의 `PODFoam_Debug`, `APMOSFoam`, `AEFoam`도 PODFoam처럼 SVD 구간마다 낡은 첫 스냅샷을

그대로 둡니다.

OpenFOAM 8이 v2212와 다른 까닭은 외부 보정이 하나일 때 케이스의 `relaxationFactors`를
OpenFOAM 8은 적용하고 openfoam.com은 적용하지 않기 때문입니다. 단순한 `pimpleFoam`도 같은
차이를 보이므로 PODFoam은 이 차이와 관계가 없습니다.

## openfoam.com의 압력 솔버

검증의 안정화한 케이스를 `p`는 PCG/DIC로, `pFinal`은 GAMG로 풀게 하고 두 단계 돌렸습니다. 그러면
각 `Solving for p` 줄이 쓰인 사전을 알려 줍니다. 실행 30회가 모두 종료 코드 0으로
끝났습니다(작업 25080017).

| 시간 단계당 압력 풀이, `nOuterCorrectors` 1 | 이미지의 `pimpleFoam` | PR 트리 | 원본 PODFoam처럼 단순한 `pEqn.solve()` |
|---|---|---|---|
| v2012, v2106, v2212 | DICPCG ×5, GAMG | DICPCG ×5, GAMG | GAMG ×6 |
| 8 | DICPCG ×5, GAMG | DICPCG ×5, GAMG | DICPCG ×5, GAMG |

- openfoam.com에서 `pimpleControl::loop()`는 마지막 외부 반복 전체에 격자의 플래그
  `finalIteration`을 켭니다. `fvMatrix::solve()`는 이 플래그로 사전을 고르므로, 외부 보정이
  하나이면 그 단계의 단순한 풀이는 모두 마지막 풀이가 됩니다.
- `pimpleFoam/pEqn.H`는 대신 `p.select(pimple.finalInnerIter())`를 넘깁니다. 이 값은 마지막
  보정의 마지막 비직교 반복에서만 참입니다.
- OpenFOAM 8은 PISO 반복과 비직교 반복마다 `singleRegionSolutionControl::updateFinal()`에서
  플래그를 다시 정합니다. 이 버전의 단순한 `pEqn.solve()`는 마지막 풀이에서만 `pFinal`을 고릅니다.
- PR 트리와 `pimpleFoam`의 `Solving for` 줄은 v2106에서 줄마다 같습니다. 외부 보정이 둘이면
  네 버전 모두에서 둘 다 외부 반복마다 DICPCG ×5와 GAMG를 씁니다.
- 인용한 소스 줄과, 이미지 안 파일과 비교한 체크섬은
  [source-excerpts.md](evidence/2026-11-02-round2/pfinal/source-excerpts.md)와
  [verify-20261102.txt](evidence/2026-11-02-round2/pfinal/verify-20261102.txt)에 있습니다.

- 모든 행렬에서 낡은 첫 열은 복사 실행의 두 번째 스냅샷과 같고, 그 뒤의 열은 실행 사이에서
  모두 같습니다.
- 저장된 U와 p는 세 실행에서 모든 저장 시각에 바이트까지 같습니다. 낡은 것은 Python이 보는 첫
  스냅샷뿐입니다.
- PODFoam의 변경 전체가 그대로 들어가는 것은 Python 연결 파일이 PODFoam과 바이트까지 같은
  `PODFoam_Debug`뿐입니다. `APMOSFoam`과 `AEFoam`에는 한 줄짜리 복사만 들어갑니다.
- 제공된 `Run_Case`는 v2106에서 세 솔버 모두 PODFoam처럼 발산하므로, v2106 행은 안정화한
  케이스를 씁니다.
- `AEFoam`은 끝까지 실행되지 않습니다. TensorFlow 2.20과 Keras 3.15에서 제공된 모듈의
  `Input(shape=(int))`가 오류를 냅니다. 솔버는 `NULL` 반환을 무시하고 다음 시간 단계에서
  세그폴트를 일으키므로, 이 행은 학습 호출 전에 쓴 행렬 하나에 기댑니다.

`End`, `Python finalized`, `FOAM FATAL`, 결정적인 메시지로 비교했습니다.

- `traps-diverging-FOAM_SIGFPE-default`에서 발산하는 실행은 openfoam.com의 PR 트리에서 SIGFPE로

  OpenFOAM 8에서는 두 빌드 모두 트랩도 `nan`도 없이 `End`까지 갔습니다.
- 트랩 시나리오 하나는 openfoam.com에서만, 다른 하나는 OpenFOAM 8에서만 돕니다.
- 제공된 스냅샷 방법을 쓰면 원본 빌드는 네 버전 모두에서 NaN이 든 POD 파일을 썼습니다. PR 트리는
  대신 `Non-finite SVD result`로 멈췄습니다.
- v2012에서는 두 rank가 `VARIANCE rank` 줄을 한 줄에 출력해 드라이버가 하나도 세지 못합니다.
  종료 코드와 메시지는 같습니다.
- `compare-rank-dependent-count`는 `bf7a06e`에서 네 버전 모두 `The ranks returned different
  numbers of POD modes: from 3 to 5`와 함께 종료 코드 1로 끝났습니다. 검토의 `fae10ba`에서는
  `MPI_ERRORS_ARE_FATAL`로 끝났습니다.

## OpenFOAM 8이 v2212와 다른 까닭

0.1초 시작 상태에서 돌린 단순한 `pimpleFoam`이 10월 30일 PODFoam 실행의 100단계 프레임을 두
버전에서 2D와 3D 모두 유효숫자 12자리까지 재현합니다. 12자리는 `pimpleFoam`이 필드를 쓰는
정밀도입니다. 가장 큰 차이는 U에서 5×10⁻¹¹ m/s, p에서 5×10⁻¹⁰ m²/s²입니다. 두 버전의 차이는
PODFoam이 아니라 OpenFOAM에 있습니다.

케이스의 `fvSolution`에는 `relaxationFactors { fields { p 0.9; } equations { U 0.9; nuTilda
0.9; } }`와 `nOuterCorrectors` 1이 있습니다. 외부 보정이 하나이면 모든 반복이 마지막 반복입니다.
v2212는 `pFinal`과 `UFinal`만 찾고, 둘 다 없고 `default`도 없으므로 아무것도 완화하지 않습니다.
OpenFOAM 8은 `Final` 항목이 없으면 `p`와 `U`로 돌아가 0.9로 완화합니다. 두 버전 모두 경고를
내지 않습니다. 소스 줄은
[source-excerpts-relax.txt](evidence/2026-11-02-round2/of8-cause/source-excerpts-relax.txt)에
있습니다.

앞의 두 행에서 두 번째 수는 OpenFOAM 8의 최대 |U| 또는 p의 범위입니다.

| 100단계 | 최대 \|ΔU\|, m/s | 최대 \|Δp\|, m²/s² |
|---|---:|---:|
| 같은 사전에서 OpenFOAM 8과 v2212: 2D | 36.9 중 3.11 | 369 중 23.2 |
| 같은 비교, 3D, 격자 전체 | 36.9 중 3.18 | 416 중 23.5 |
| 블록을 뺀 OpenFOAM 8과 v2212: 2D | 0.0000 | 0.0001 |
| 같은 비교, 3D | 0.0001 | 0.0005 |
| `pFinal 0.9`와 `UFinal 0.9`를 넣은 v2212와 OpenFOAM 8: 2D | 0.0000 | 0.0001 |
| 방정식 계수 `U`, `nuTilda`만 둔 OpenFOAM 8과 v2212: 2D | 3.11 | 23.2 |
| 필드 계수 `p`만 둔 OpenFOAM 8과 v2212: 2D | 0.0093 | 0.105 |
| 두 버전 모두 완화 없이 한 단계만, OpenFOAM 8과 v2212: 2D | 1.0×10⁻¹⁰ | 5.0×10⁻⁹ |

- 차이는 U 방정식의 계수에서 옵니다. 층류 케이스라 `nuTilda`는 풀지 않습니다.
- v2212는 블록이 있든 없든 같은 필드를 냅니다. OpenFOAM 8도 `Final` 항목을 따로 적든 적지 않든
  같습니다.
- 3D에서 압력 풀이당 반복 수는 OpenFOAM 8에서 블록이 있으면 67.9, 없으면 24.4로 v2212와
  같습니다. 처음 100단계의 평균입니다.
- 10월 30일 보고서는 110단계 전체의 평균 64.0과 23.5를 적었습니다.
- 두 버전의 케이스에서 `fvSchemes`와 `turbulenceProperties`는 같습니다. `controlDict`는 v2212의
  `libs` 줄 하나만 다릅니다.
- `Run_Case`는 블록을 그대로 두므로 결과는 한 버전 안에서 비교합니다.
